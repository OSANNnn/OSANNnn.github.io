The ISAAC Protocol

Unreal Engine 5 · C++ & Blueprints · Team of 6 (4 programmers, 2 designers) · 3 months

ROLE: team lead + gameplay programmer

A sci-fi escape-room puzzle game: you wake up alone on a deserted space station, and the only help you have is ISAAC, a robot companion. Many puzzles need both of you, so the work is split between the player and the robot.

Final project of the DigitalBros Game Academy course. The lead role grew naturally within the team, and along the way I built two of the game’s core systems in C++.

Full breakdown: everything I worked on

What I built

  • Interaction system (C++): instant, timed and hold interactions, with focus detection on what the player is looking at
  • Puzzle framework (C++): a world subsystem that tracks every puzzle, configured through data assets and gameplay tags, unlocking doors and areas as groups of puzzles are solved. A naming component tags who is interacting, so a puzzle can require the player, ISAAC, or both
  • Puzzles and room access: valves, a door that needs an ISAAC override before it unlocks and slides open, and force fields that seal off each room until a specific puzzle group is completed, then switch off and open the path for ISAAC’s navigation too
  • ISAAC’s AI: helped rebuild it from scratch
  • Controller support: HUD button prompts that switch between keyboard and mouse or gamepad, plus input UI for widget-based puzzles like the battery grid
  • Main menu: two cameras, one moving to a monitor in the scene where the credits play as an in-world widget
  • Ending sequence: the ship starts up, the point of view changes and the camera shakes, then the game moves into a dedicated, more cinematic ending level
  • Inventory: the basic functionality, built with a teammate

Leading the team

  • Acted as the bridge between design and programming
  • Spotted what needed doing, organized the tasks and kept track of progress
  • Kept the repository healthy and built the C++ binaries for the designers after each new feature
  • Tested new features so the project stayed free of crashes and errors
  • Packaged the alpha, beta and release builds
  • Taught the designers Git in a 3-hour lesson and helped them out of binary merge conflicts

OpenGL Renderer

C++ · OpenGL · GLSL · Solo

A real-time 3D renderer built while working through LearnOpenGL. I followed its techniques but designed my own architecture: buffers, framebuffers, textures, cubemaps and shaders are wrapped in C++ classes, so the render loop reads like a scene instead of a wall of API calls. My first real OOP project, grown chapter by chapter.

  • C++
  • OpenGL
  • GLSL
  • GLFW
  • GLM
Source code

Features

  • Phong lighting with directional, point and spot lights, plus emission maps
  • 3D model loading with diffuse and specular textures
  • Cubemap skybox with reflection and refraction
  • Geometry shader effects: mesh explode and normal visualization
  • Framebuffer post-processing (blur, grayscale, edge detection, sharpen), chainable
  • Alpha-blended foliage sorted by camera distance

Arduino Maze

C++ · Arduino · Team of 2 · School project, ~2 months

A first-person 3D maze in the style of Wolfenstein 3D, running on a real Arduino with a small TFT screen. I wrote the game logic and the raycasting renderer, managing memory by hand and optimizing until it fit the microcontroller’s limits.

My teammate handled the hardware and low-level input, and built an SDL framework that simulated the display library so we could test on PC.

  • C++
  • Arduino
  • Raycasting
  • Embedded
Source code

Features

  • Raycasting renderer with the DDA algorithm, one ray per screen column
  • Wall colors by tile type, with side shading for depth
  • Minimap with fog of war that reveals the areas you explore
  • Per-axis collision, so the player slides along walls
  • Frame-rate independent movement and rotation with delta time
  • Scene flow: main menu, loading, game, minimap and game over
  • Manual memory management to fit the Arduino’s limited memory and clock speed

ASCII Dungeon

C++ · Win32 API · Solo experiment

A small rogue-like that runs entirely in the Windows console, built straight on the Win32 API with no game libraries. Input comes from the keyboard state, and each frame only rewrites the characters that changed instead of reprinting the screen, so nothing flickers. Levels are plain text files, in the spirit of Rogue.

  • Real-time input polled with GetAsyncKeyState
  • Partial redraws through SetConsoleCursorPosition
  • Levels loaded from text files with a size and spawn header
  • Tile-based collision against walls
  • C++
  • Win32 API
  • ASCII rendering

03About

Before I wrote a line of code, I spent over a decade in restaurant management: coordinating teams and keeping service running under pressure.

Then I went back to school while working full time, finished my IT diploma with 100/100, and went straight into the DigitalBros Game Academy. That background is why the lead role on The ISAAC Protocol came naturally: keeping a team moving is something I’d been doing for years.

I enjoy every part of game programming, from gameplay and UI to physics, but computer graphics is where I’m heading: how a frame comes together, what makes it fast, and what makes it look right. I learn by building, studying the best resources out there, and taking my own code apart to make it better.

Away from the code I’m usually playing something, or staring at a screenshot wondering how they lit that scene. Good code is only half of a good game, and I care about the art and design half too.
